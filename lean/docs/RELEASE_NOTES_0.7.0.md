# Lean VS Code v0.7.0 release notes

v0.7.0 keeps editing, local review, terminal, search, and optional extensions while removing an unused packaged window and simplifying macOS shell-environment collection. It makes no new public startup or runtime-memory percentage claim. The signed installed-app comparison is against original Code-OSS from the fork's base revision `04c0d99f4fb0d8afe6ce4f0c58e31e183ac3e4b1`, built in the same minified mode.

## Changes

- Retain the v0.6 Node compile cache for extension host, shared process, and terminal host. A main-process cache experiment was removed from v0.7 after exploratory paired trials showed no reliable tail-latency improvement.
- For macOS zsh, bash, and sh, use the system `env -0` command to read the login-shell environment without launching another Electron process to serialize it. The same login and interactive shell flags, cancellation, timeout, and environment cleanup remain; other shells keep the original collector. Focused parser and real-shell tests pass. A direct old/new login-shell comparison found the same 80 environment keys and identical `PATH`, `HOME`, and `SHELL`; zsh's optimized final command changes `SHLVL` and `_`, so the native path normalizes those to legacy values. A non-GUI subprocess probe suggests about 59 ms collector overhead can be removed, but the final app-level startup impact is still under test.
- Omit the separate Agents-window resources from the desktop package. The installed v0.6 app contained 21,542,445 bytes in `out/vs/sessions`; the signed v0.7 app contains no such directory. An Agents-window request opens a regular editor window. The fallback code maps an older Agents workspace to an ordinary workspace; that restoration path was not separately exercised in the final GUI checks.
- Make the startup trace warm-up quit through the editor. A signal-killed warm-up could leave Node's compile cache unwritten, so the trace now fails if the warm-up cannot quit normally. The benchmark also supports focused extension-backed startup trials and independent paired memory launches.

## Evidence and release gates

- **Final build and static checks:** the minified app was built from product commit `a494193286d97236cbc59d0ecfa2232a2dfa80e5` and reports v0.7.0. Typecheck, changed TypeScript lint, focused shell tests, and `lean:check-ai` passed; the AI guard found all 87 required extension API actors. The release package includes 33 curated bundled extensions and no `out/vs/sessions` bundle. Repository ESLint still rejects the existing Lean `.mjs` scripts under its JavaScript-file policy; that is not a new runtime failure.
- **Final signed-app functional checks:** a 560 × 360 bottom-left window passed edit/save verified on disk, 401-file project search and ten text matches, an integrated-terminal command, a local Git diff, and an extension webview. Open VSX EditorConfig 0.18.2 installed with a successful Ed25519 signature check, activated on startup, and processed `sample.ts`. A `--agents` request opened a regular editor window at the requested bounds. These checks used isolated profiles and did not benchmark elapsed time.
- **Package and trust checks:** the signed, notarized update ZIP and DMG contain identical app entries. The extracted app passed strict deep code-signature verification, stapled-ticket validation, and Gatekeeper assessment; the DMG's stapled ticket validated. The ZIP is 192,164,046 bytes with SHA-256 `98977293c35a31609929d1be0f18974caff4e27f432803fe73f8697b46f27eb1`. The DMG is 205,598,994 bytes with SHA-256 `152c5a7c3cd43ad9e3727ce77ba8642bcc16019706a1c1294fe60baa96ccdc75`. The static update feed records the ZIP's hash and size.
- **Installed size:** the [signed v0.7.0 app-bundle report](../performance/v0.7.0-bundle-size-vs-code-oss-1.139.1-minified.json) measured 513 versus 1,463 MiB of apparent content against original same-revision minified Code-OSS: **64.9% smaller**. This does not measure runtime memory or compare DMG download sizes.
- **Exploratory performance evidence:** the main-process cache experiment wrote about 3.4 MiB and a trace measured `import(main.js)` at 120 ms. A nine-pair candidate-versus-v0.6 trial found 1,362 vs 1,387 ms median editable-file time, but worse candidate p95 (1,623 vs 1,505 ms). A 30-pair compact-window trial also had worse candidate p95 through pair 24, then both apps slowed sharply under host load. We removed the cache and make no v0.7 startup claim from those runs. A [nine-pair short-idle candidate trial](../performance/v0.7.0-candidate-compact-memory-vs-code-oss-1.139.1-minified.json) against original minified Code-OSS measured 573 vs 706 MiB median app-tree footprint after 30 seconds with fresh profiles and identical small windows. Lean was lower in seven of nine pairs. Both GPU processes showed bimodal footprints; no v0.7 runtime-memory percentage is promoted from this candidate trial.
- **Current shell candidate startup diagnostic:** in [nine alternating compact-window established-profile pairs](../performance/v0.7.0-shell-candidate-vs-v0.6.0-compact-startup-diagnostic.json), the locally signed candidate reached an extension-editable file in 1,396 ms median / 1,528 ms p95 versus 1,484 / 2,654 ms for installed v0.6. The candidate was faster in all nine pairs, including a v0.6 outlier; the comparison includes the Agents-bundle omission and does not isolate the shell change. It is not a public Code-OSS speed claim.
- **Publication and update:** the [v0.7.0 GitHub release](https://github.com/mattivilola/lean-vs-code/releases/tag/v0.7.0) contains the verified DMG, ZIP, and feed. The live `releases/latest` feed advertises v0.7.0 with the expected ZIP hash and size. The owner confirmed the in-app v0.6 → v0.7 update works; the installed `/Applications/Lean VS Code.app` reports version 0.7.0 and bundle ID `com.mattivilola.leanvscode`, and its strict deep code-signature verification passes.
- **Benchmark cadence:** the full paired GUI suite runs only for major releases or an explicit owner request. The final v0.7 full run was stopped at the owner's request; its partial observations are not used. Focused checks and a direct bundle-size comparison are sufficient for this minor release. Earlier v0.6 speed results remain labeled as v0.6.

The sub-second p95 extension-backed editable-file target remains open until a signed build demonstrates it. Earlier v0.6 figures remain labeled as v0.6 in the [performance history](PERFORMANCE.md); they do not automatically apply to v0.7.
