# Lean VS Code v0.8.0 release notes

v0.8.0 retains the focused editor, local Git review, terminal, search, and extension platform while reducing optional AI compatibility code in the initial renderer graph. Built-in chat and agent UI remain absent. This minor release makes no new startup or runtime-memory percentage claim; the full paired GUI comparison is reserved for a major release or an explicit owner request.

The signed release app is **64.9% smaller by apparent file content** than the preserved, locally repaired original Code-OSS 1.139.1 minified source package at the same upstream revision: 514 versus 1,463 MiB. This is a disk-content comparison, not a runtime-memory or download-size result. See the [bundle-size report](../performance/v0.8.0-bundle-size-vs-code-oss-1.139.1-minified.json).

## Changes

- Load the retained Quick Chat service renderer on demand through a synchronous-service-compatible proxy. Six focused headless proxy tests passed. Lean's built-in AI UI is removed, so the upstream Quick Chat action is not exposed in the desktop app.
- Keep retained terminal chat attachment code, chat-pet rendering, and image hashing from pulling broader chat UI or paste-provider modules into the initial graph. The [ledger](OPTIMIZATION_LEDGER.md) and linked static-graph reports record each cut, its validation, and rejected experiments. The desktop initial static graph is 31,520,121 unminified JavaScript bytes. This is a parse-work opportunity, not a measured startup saving.
- Preserve the registered services and all 87 extension API actors. `npm run lean:check-ai` passed with zero missing dependency registrations.

## Validation

- Client typecheck and changed-file lint passed. Focused tests passed for the Quick Chat proxy (six headless Chromium cases), pet-host coordination (five), image hashing (Node known vectors and offset view), and paste providers (five headless Chromium cases).
- The production-minified Apple Silicon release app was built from product commit `cd1c632c1de880b9251cbbe0b737946d88359fb1` with Node 26.9.0 and npm 11.19.1. It reports Lean v0.8.0 and Code-OSS extension API 1.139.1, contains 33 curated bundled-extension directories, and has no separate `out/vs/sessions` bundle.
- An [isolated functional-only check](../performance/v0.8.0-source-functional-smoke-no-timing.json) on an ad-hoc-signed copy of that build passed edit/save, project and text search, terminal output, local Git diff, and a temporary extension webview. The app used a 560 × 360 bottom-left window. No startup or per-check timing was collected; this does not validate an installed Open VSX extension or a signed release.
- A separate [Open VSX functional check](../performance/v0.8.0-source-editorconfig-functional-no-timing.json) installed EditorConfig 0.18.2 into an isolated profile. Signature verification succeeded, the extension activated, and its output log shows it processed `src/main.ts`. This was also a compact-window, no-timing run on the source candidate, not the final signed app.
- The [final signed-app functional checks](../performance/v0.8.0-release-functional-no-timing.json) repeated six core workflows and installed EditorConfig 0.18.2 from Open VSX. Its signature verification succeeded, and it activated and processed a TypeScript file. These checks used isolated profiles and a 560 × 360 bottom-left window without collecting startup or per-check timings. A macOS trust-store certificate parsing message and Node `url.parse()` deprecation warning appeared in logs without failing the checks.
- The signed and notarized updater ZIP and DMG contain matching app entries. Strict deep code-signature verification passed, both stapled tickets validated, and Gatekeeper accepted the extracted app as Notarized Developer ID. The ZIP is 192,313,040 bytes with SHA-256 `c8d16cccd047ddc9cc33bf920c66f015e4fce2c78de324ba44fe21e8bbc1efe4`; the DMG is 205,127,879 bytes with SHA-256 `d6eb112d99d0323310693ea099af9a49c21688c0f52be349c95f5dd4be8f9a0c`. The static update feed matches the ZIP's hash and size.
- An earlier three-pair fresh-profile diagnostic of the Quick Chat split versus installed v0.7.0 was mixed and is recorded in the [candidate report](../performance/v0.8.0-cold-renderer-split-candidate.json). It cannot support a speed claim for this later source candidate or against Code-OSS. The owner has deferred further GUI timing until requesting a combined test.

## Publication and remaining checks

The retained chat and paste code passed focused headless tests. Its upstream UI flows are not reachable in Lean because the built-in chat contribution is omitted; their real first-use behavior was not claimed as a user-facing release feature. The [v0.8.0 GitHub release](https://github.com/mattivilola/lean-vs-code/releases/tag/v0.8.0) contains the verified DMG, ZIP, and feed. The live latest-release feed advertises v0.8.0 with the expected ZIP hash and size. An installed v0.7-to-v0.8 update remains to be confirmed by the owner; the current `/Applications` app was still v0.7.0 at publication. The sub-one-second p95 editable-file target remains open until a signed matched comparison proves it.
