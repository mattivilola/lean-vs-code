# Lean VS Code v0.5.0

v0.5.0 starts local extension initialization as soon as the workbench reaches Ready, removing a further idle-callback wait. The editor, local Git review, integrated terminal, search, webviews, and optional extensions remain available. Experiments that did not show a useful file-ready gain were left out: extension-host prewarm, an optional AI editor split, a macOS-only bundle variant, and initialization before the Ready lifecycle boundary. The [optimization ledger](OPTIMIZATION_LEDGER.md) records why.

On an Apple M3 Max, the signed and notarized v0.5.0 release reached an extension-editable 100 KiB file in **1,653 ms median / 2,009 ms p95** across 30 alternating warm-cache launches. A locally repaired, production-minified original Code-OSS 1.139.1 source build from the same upstream revision measured **1,960 / 2,254 ms** in that run: **16% less median launch-to-editable time** for Lean. All 60 launch checks passed. The [sanitized raw observations](../performance/v0.5.0-vs-code-oss-1.139.1-minified.json) and [method](PERFORMANCE.md) include the already-running-window and short-idle diagnostic readings. The p95 target below one second remains unmet. Different sessions have different absolute timings; the percentage uses only the paired v0.5.0 run, not v0.4.0's earlier baseline.

The signed v0.5.0 app bundle contains **537.7 MiB** of apparent file content, compared with **1,462.9 MiB** in that matched Code-OSS package: **63.2% less** by the [bundle-size report](../performance/v0.5.0-bundle-size-vs-code-oss-1.139.1-minified.json). The v0.5.0 DMG is **211.3 MB**. No matched Code-OSS DMG was measured, so there is no download-size saving claim. Three idle-memory snapshots from one launch per app appear in the benchmark report, but they are not an independent memory comparison. The separate [nine-pair v0.4.0 short-idle result](../performance/v0.4.0-independent-memory-vs-code-oss-1.139.1-minified.json) remains labeled as historical evidence for that version only.

The minified app passed an isolated GUI smoke before signing and again after extraction from the update ZIP: editing and saving, 400-file text search with 10 verified matches, an integrated terminal command, local Git diff retrieval, and extension webview creation. The signed app installed EditorConfig 0.18.2 from Open VSX in an isolated profile; its log reports successful signature verification. These checks confirm the exercised paths, not universal extension compatibility.

The update ZIP and DMG contain identical file bytes and symlink targets across **2,213 app-bundle paths**. The app and DMG passed strict Developer ID signature, Apple notarization, stapled-ticket, and Gatekeeper checks. The ZIP's SHA-256 and byte count match the static update feed. The bundled app reports version **0.5.0**, identifier `com.mattivilola.leanvscode`, Code-OSS extension API **1.139.1**, and runtime source commit `54c34564533574341305096431de244e8fa2eb60`. The release remains Apple Silicon-only. A native update trial from the signed v0.4.0 app is recorded after the public feed is published.
