# Lean VS Code v0.4.0

v0.4.0 makes the Apple Silicon app quicker to reach an editable file. The macOS release now uses the production-minified Code-OSS bundle. Startup also avoids an eager remote-service listener lookup, and the shared utility process begins its existing initialization after the first real window opens. These changes preserve the editor, local review, terminal, and extension APIs rather than removing them to shorten a launch trace.

In a **30-pair, same-session comparison of signed releases** on an Apple M3 Max, v0.4.0 reached an editable file in **1,239 ms median / 1,268 ms p95**. Installed v0.3.2 measured **1,310 / 1,353 ms**. That is **5% less median time** and **6% less p95 time** for this 100 KiB file and isolated-profile test. The [public observations](../performance/v0.4.0-vs-v0.3.2.json) and [method](PERFORMANCE.md) make the comparison inspectable. The target of p95 at or below one second remains open.

A separate 30-pair trial against original Code-OSS 1.139.1 source at the same upstream revision measured **1,262 / 1,310 ms** for signed v0.4.0 and **1,608 / 1,727 ms** for Code-OSS. That Code-OSS app was built without production minification, so the **22% median difference is specific to that labeled source build**, not a claim against an equally optimized or official VS Code distribution. An optimized Code-OSS comparator was attempted but excluded: the upstream packaging task omitted Copilot runtime files, and the repaired local app failed repeated file-ready launches. Its failed trial is not mixed into the public result. See the [labeled observations](../performance/v0.4.0-vs-code-oss-1.139.1.json).

Idle app-tree memory did **not** show a reliable improvement. In the direct v0.3.2 comparison, v0.4.0 measured 786 MiB median versus 733 MiB for v0.3.2. In the separate Code-OSS run, the same v0.4.0 bundle measured 650 MiB. Each run samples one launched app tree three times after a 30-second idle period; those snapshots cannot explain the large between-run shift. No lower-memory claim is made for v0.4.0, and further release work will test it across independent launches.

The signed app passed a GUI smoke after installation in `/Applications`: editing and saving, workspace file search, an integrated terminal command, a local Git diff, and an extension webview all worked in an isolated profile. EditorConfig 0.18.2 installed from Open VSX in another isolated profile of the signed app, with signature verification reported as successful; a local VSIX also installed and listed. The client TypeScript check, focused remote-service and sidecar suites, and 97 build/minifier tests passed during implementation. A bundled-extension manifest index and early extension scan were trialed but not retained because they gave no file-ready gain.

The update ZIP and DMG contain **identical bytes and symlink targets across 2,236 app-bundle paths**. The app and DMG passed strict Developer ID signature, Apple notarization, stapled-ticket, and Gatekeeper checks. The feed's ZIP hash and size match the artifact. The installed app reports bundle version 0.4.0 and identifier `com.mattivilola.leanvscode`; the Code-OSS extension API remains 1.139.1. The embedded product commit `e54bdc8388a053f7ca6921bb6c67bea28c3ead01` identifies the last runtime-code commit; release-version metadata was committed afterward. The release is for Apple Silicon macOS and includes the existing GitHub-hosted updater.
