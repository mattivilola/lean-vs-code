# v0.11 startup investigation

The current signed v0.10 result is 1.471 s median / 1.596 s p95 to an extension-editable requested file, versus 1.903 / 2.141 s for original same-revision minified Code-OSS. The sub-second p95 target remains open. The next scheduling change needs a current trace showing a material delay; smaller optional-code cuts can be retained with source-graph and correctness evidence, without assigning them latency or memory gains.

## Source boundaries reviewed by GPT-6 Astra

The focused review on 30 September 2026 identified three optional boundaries. Its initial byte estimates came from existing emitted JavaScript with matching inline source maps; they are estimates, not rebuilt bundle deltas.

| Candidate | Safe boundary | Required invariants |
| --- | --- | --- |
| Main MCP HTTP routes/sessions | Extract the route implementation and load its constructor during the existing asynchronous first server start. | Keep the service/channel registered; load before accepting requests; synchronous server-change handling; deduplicate server starts; no late gateway after disposal or disconnect. |
| Shared-process browser automation | Register initialization options immediately; load Playwright implementation on the first real operation. | Preserve unawaited client initialization, per-context instance ownership, synchronous unsupported-event rejection, shared construction, retry, receiver/arguments/results, and disconnect/reconnect identity checks before construction and dispatch. |
| Shared-process remote CLI installer | Defer both SSH and dev-container installer imports to their existing asynchronous call sites. | Preserve channels, authentication, platform detection, command escaping, install/fallback outcomes and caller error handling. Both static edges must move. |

The main agent-host starter is already demand-driven at process-launch level. Preserve its early IPC, policy and shutdown listeners. Playwright's external package is already dynamically imported; no additional saving from that package is assumed. A whole ChatService proxy remains unsuitable because of synchronous model/reference/event contracts.

## Rejected main-process loading experiment

The [MCP route report](../performance/v0.11.0-mcp-gateway-route-lazy-cut.json) initially recorded an isolated `app.ts` graph with experimental splitting: 2,070,863 to 2,055,580 unminified static JavaScript bytes, **15,283 fewer**. This was a prospective graph, not the production package. Pipeline inspection found that main/bootstrap builds remain unsplit: dynamic imports defer initialization but their code still lives in the same file. An otherwise matched unsplit graph grew from 2,070,863 to 2,119,926 bytes (**49,063 more**). Reject the lazy-route import without a current trace establishing a benefit. The final candidate uses a static route import; the prospective byte saving is not a retained optimization.

Keep the route source boundary and lifecycle fixes discovered while testing. Eight real local-HTTP/lifecycle tests and sixteen existing session tests pass on Node 24.21.0. The first test draft omitted the required MCP `notifications/initialized` handshake and correctly received a protocol error. The fixture was corrected; protocol behavior was preserved. Service-disposal and client-disconnect checks prevent late gateways. A fault-injected HTTP-module load confirms error propagation and retry. Disposing at socket listening rejects startup without a late callback error; cancellation clears its timeout.

The [remote CLI installer split](../performance/v0.11.0-remote-cli-installer-rejected.json) was also reverted: moving both imports grew its exploratory shared-process static graph by 1,397 unminified bytes. The installer remains intact, and its existing helper suite passed 102 tests. This was source evidence, not a remote connection or GUI test.

## Retained shared-process boundary

Astra recommended a separate, scoped shared-process experiment before considering a main/bootstrap split. Switching only that entry from `outfile` to an explicit stable entry path under `outdir`, with its own chunk namespace, initially preserved the shared bundle byte-for-byte: **1,176,112 minified/NLS bytes**, SHA-256 `005fd525b0a800bce28e53c23fdd5b0a0c5fcfdb5b913c417355e0011b1411d9`. The main output also remained byte-identical in that configuration-only check. Main/bootstrap, extension-host and terminal bundling options are unchanged.

With that boundary in place, defer the Playwright service until the first operation. Register copied window options immediately because the client does not await initialization. Deduplicate construction per context; preserve first initialization options, receiver, arguments, results and method errors. Check context identity before construction, after construction and immediately before dispatch. A disconnected/reconnected context cannot be overwritten by an old load. Idle `disposeSession` returns without loading, while cleanup during a pending operation waits behind it. The interface exposes no events, so unsupported event listeners still reject synchronously and do not trigger loading.

The [exact minified source-build report](../performance/v0.11.0-shared-playwright-lazy-cut.json) includes the entry and its eager common chunk, excluding the optional module and source maps. Initial shared-process JavaScript falls from **1,176,112 to 1,164,843 bytes (11,269 fewer)**. Total shared-process JavaScript grows to **1,180,023 bytes (3,911 more)**; the optional service module is 15,180 bytes. This is a loading metric, not a measured startup or memory result; total JavaScript growth is recorded separately. Ten channel/lifecycle tests plus the existing Tab network-filter test pass, including real first-use module loading without starting a browser. The built optional module also imports and disposes an unused session directly in Node. Its three JavaScript files parse and all three internal import targets resolve. Production minification/NLS/private-field builds, typechecks, lint, 58 build-helper/NLS/map tests and the AI/DI/87-actor guard pass.

The first test draft referenced an unexported IPC `Connection` type. Typecheck caught it; the fixture now derives the connection type from the public server surface. No production IPC contract changed.

Actual main/bootstrap splitting remains a larger, untried design. It would change the bootstrap-to-application dynamic import and needs explicit proof that `import.meta.dirname`, product metadata, portable paths and NLS initialization retain their required locations. Do not enable it merely to make the prospective MCP graph smaller.
